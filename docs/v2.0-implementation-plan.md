# Loop v2.0 实施计划（存储重构 + Project/Habit + Node MCP）

> 配套文档：`docs/PRD.md`（v2.0）、`docs/database-design.md`（v2.0）。本文件是把 PRD/设计落到代码的**分阶段执行计划**。

## Context

`docs/PRD.md` 与 `docs/database-design.md` 已升级到 **v2.0**，这是一次架构重构，不是增量功能。核心变化：

1. **存储引擎切换**：Markdown 日文件（`YYYY/MM/*.md`）→ **SQLite（`data.db`，本地查询权威）+ append-only op log（`ops/*.jsonl`，同步真实来源）**。
2. **新增两种实体**：`Project`（有终态的目标，带 markdown body + 关联 entry）、`Habit`（持续习惯，按 `schedule.match` 动态统计）。
3. **Entry 新增 `ongoing` 状态**（持续进行中，不打勾）。
4. **同步从文件级合并 → op-level 合并**（op 并集按 ULID 排序去重 + 回放）。
5. **MCP server 由 Rust（读 markdown，stdio）重写为 Node.js**（共享 `data.db` WAL + `ops/`，stdio + WebSocket 9710/9711 桥，覆盖三种实体）—— 已确认采用 PRD §5.2 方案。

**本次约束（用户明确）**：**不考虑旧数据迁移**。因此直接以 SQLite + op log 替换 markdown 主存储，删除 markdown 读/写主路径（`parser.ts`/`serializer.ts`/`Vault` 日文件逻辑），markdown 仅保留为"按需导出快照"格式。无需写 markdown→SQLite 导入器。

**交付方式（用户明确）**：完整计划一次性记录，但**分阶段执行**。下面按可独立推进的 Phase 组织。

**范围裁剪（用户明确）**：**in-app AI 功能不在 v2.0 范围**——不实现「问 AI」按钮、in-app AI 调用层、AI 配置页、Prompt 模板管理页（PRD §4.7.2/§4.7.3/§4.8.1 暂不实施）。MCP server（PRD §4.8.2）保留。

### 当前代码现状（v1.x，已勘察）

- Monorepo：bun workspace。`packages/core`（TS 共享逻辑，Vitest）、`apps/desktop`（Tauri 2 + React + Zustand）、`apps/mobile`（RN，仅 Android scaffold）、`apps/mcp-server`（**Rust**，stdio，读 markdown）。
- `packages/core`：单一 `Entry` 实体（`status: 'todo'|'done'|'log'`），`FileSystem` 抽象（`fs.ts`），`Vault` 类做日文件 CRUD（`vault.ts`），文件级 `sync()`（`sync.ts` + `webdav.ts`），`parser.ts`/`serializer.ts` 处理 markdown，`ulid.ts`/`tags.ts`/`metadata.ts`/`capture.ts`/`commands.ts`/`search.ts`/`reminders.ts`/`settings.ts`。`capture.ts` **已支持** `@time`→`due`、行尾 `!`/`!!`/`!!!`→`priority`（PRD 视作 Level 1，但已落地）。
- 桌面端较成熟：HashRouter 路由、`WelcomeScreen`（创建/打开/WebDAV 三选项）、同步状态机（含将被移除的 `pull_required`）、`McpServerPage`（health check）、`ConflictsPage`、keychain 桥、`export_vault`。**无** Project/Habit 屏、无 SQLite、无 op log。
- 移动端：Zustand `vaultStore`、10 个屏、`react-native-fs` 存 markdown、Notifee 通知；仅 Android 原生工程，**无 iOS/HarmonyOS**。

### 目标产物

把三端 + MCP 全部切到 SQLite + op log 架构，落地 Entry(`+ongoing`)/Project/Habit 三实体与对应 UI、op-first 写入与重建、op-level 同步、Node MCP server。

## 贯穿全程的不变量（PRD §1.5.5，任何 Phase 都要遵守）

1. **Op 优先写**：所有写操作必须 **先成功 append op → 再 apply 到 SQLite → 再更新 UI**；op 落盘失败即中止，不得污染 SQLite / UI。
2. **幂等**：同一 op 凭 `applied_ops` 判重，应用两次结果一致。
3. **本地库可丢弃**：删除 `data.db` 后启动从 op log 完全重建；提供「重建本地数据库」入口（桌面 Cmd/Ctrl+R）。
4. **路径边界**（§1.5.6）：所有文件操作（含 MCP）执行前校验在 vault 根内、不在排除目录（`.local/`、`exports/`）。
5. **同步范围**：仅 `ops/`、`attachments/`、`config.json` 参与 WebDAV 同步；`data.db*`、`exports/`、`.local/` 不同步。
6. **规则克制**（§1.5.7）：不新增超出 PRD 的输入语法/实体/控件。

## 新 core 分层（架构总览）

```
packages/core/src/
  storage.ts      [新] Storage 抽象（SQLite 访问：exec/query/transaction），各端注入实现
  fs.ts           [保留] op log / attachments / exports 的文件 IO 抽象
  schema.ts       [新] DDL（entries/projects/habits/entry_tags/project_tags/sync_meta/applied_ops）+ schema_version + 迁移
  oplog.ts        [新] Op 类型、jsonl 序列化/解析、ops/YYYY/MM/YYYY-MM-DD.jsonl 路径与 append
  apply.ts        [新] 单 op apply 引擎：幂等(applied_ops)、LWW、删除墓碑、schema_version 升级层
  rebuild.ts      [新] 扫 ops/ → 回放 → 重建 data.db（含一致性校验）
  db.ts           [新] LoopDB 编排器（取代 Vault）：写=compute op→append→apply→返回；读=SQL
  repo/entries.ts repo/projects.ts repo/habits.ts  [新] 各实体读查询 + 写 op 构造
  habits.ts       [新] schedule.match 动态匹配、周期进度、热力图聚合
  config.ts       [新] config.json 作为 op-log 派生（config.set/unset op）
  sync.ts         [重写] op-level 合并（文件清单对比→op 并集 sorted_unique_by_id→apply 新 op）
  search.ts       [重写] SQL 跨实体查询 + 搜索语法(type:/status:/date:/project:/#tag)
  capture.ts commands.ts tags.ts ulid.ts metadata.ts reminders.ts settings.ts  [保留/微调]
  types.ts        [扩展] EntryStatus 加 'ongoing'；新增 Project/Habit/Op/HabitProgress 类型
  parser.ts serializer.ts  [降级]：仅供「导出 markdown 快照」复用，移出主存储路径
  vault.ts        [移除]：日文件 CRUD 不再使用（导出可抽取所需片段）
```

平台 `Storage` 绑定：桌面 `tauri-plugin-sql`(sqlx)；移动 `react-native-quick-sqlite`；鸿蒙 `@ohos.data.relationalStore`（后置）；Node MCP `better-sqlite3` 或 `node:sqlite`。

## Phase 0 — 准备（依赖与脚手架）

- 根 `package.json`（`workspaces` 字段）：确认 workspace；为 Node MCP 新建 `apps/mcp-server-node`（或在确认弃用 Rust 版后替换 `apps/mcp-server` 内容）。
- 桌面：`apps/desktop/src-tauri/Cargo.toml` 加 `tauri-plugin-sql`（feature `sqlite`），`tauri.conf.json`/capabilities 放开 sql 权限；`src-tauri/src/main.rs` 注册插件、初始化 `data.db` 开 **WAL**。
- 移动：`apps/mobile` 加 `react-native-quick-sqlite`（Android 先行）。
- 引入本地时间解析依赖已存在（`chrono-node` 在 capture 中），无需新增。

## Phase 1 — core 存储基座（最关键，先行）

落地后 `packages/core` 可在内存/桩 Storage 上完整跑通"写 op→apply→查 SQL→回放重建"。

1. `types.ts`：`EntryStatus` 增 `'ongoing'`；新增 `Project`、`Habit`、`HabitSchedule`、`HabitProgress`、`Op`（通用结构 + 各 `kind` payload，见 PRD §6.3.2）。`Entry` 增 `project_id: string|null`。
2. `storage.ts`：定义 `Storage` 接口（`query<T>(sql,params)`、`exec(sql,params)`、`transaction(fn)`）。提供 `MemoryStorage`/或基于 `better-sqlite3` 的测试实现供 Vitest。
3. `schema.ts`：PRD §6.2 全部 DDL（entries、entry_tags、projects、project_tags、habits、sync_meta、applied_ops + 索引）；`schema_version` 常量与建库函数。
4. `oplog.ts`：Op ULID、`at`、`device_id`、`schema_version`、`kind`、`payload`；jsonl 序列化/解析（坏行跳过、记录错误，§10.3）；`ops/YYYY/MM/YYYY-MM-DD.jsonl` 路径与 append（经 `FileSystem`）。
5. `apply.ts`：实现 §6.3.3 应用规则——`applied_ops` 幂等、ULID 时间序、LWW、`*.delete` 墓碑（迟到 update 跳过）、`schema_version` 升级层。覆盖 entry/project/habit/config 全 kind。
6. `rebuild.ts`：扫描 `ops/` 全量按 id 排序回放重建 `data.db`；启动一致性校验（SQLite 与回放不一致→报 error 引导重建）。
7. `db.ts`（`LoopDB`）：统一写路径 `append→apply→返回`，读路径走 repo。取代 `Vault` 被 UI/store 依赖的方法面（`createEntry`/`updateEntry`/`setProperty`/`completeEntry`/`deleteEntry`/`listEntries`/`getEntry` + project/habit 版本）。
8. `repo/*.ts`：实体读查询与写 op 构造。
9. **Vitest**（参照 §10.3 最小集）：单 op create/update/delete、update-after-delete 跳过、重复 apply 判重、回放重建、`project.delete`→entries.project_id 置 NULL、`habit.update` 改 target 即时重算、坏 jsonl 跳过。

## Phase 2 — core 领域逻辑

1. `sync.ts` 重写：op-level 合并（§6.4）——列本地/远端 `ops/*.jsonl`，size/hash 对比，必要时解析双方 op 取并集 `sorted_unique_by_id` 写回两端，apply 新 op，更新 `sync_meta.last_sync_at`；attachments 按 mtime newer-wins。移除文件级 `mergeDayFiles`/`.conflicts` 旧逻辑。
2. `habits.ts`：按 `schedule.match`（MVP `{tag}`）动态匹配 entries，计算本周期 `n/min-max` 与历史热力图（默认 12 周期）。
3. `search.ts` 重写：SQL 跨 entry/project/habit；搜索语法 `#tag`/`type:`/`status:`/`date:`/`project:`（AND）。
4. `config.ts`：`config.json` 经 `config.set`/`config.unset` op 同步（含 `ui.ongoing_pinned`、`tagColors`）。
5. `capture.ts`/`commands.ts`：新增 `/ongoing` 命令；capture 输出改为驱动 op 构造（content/tags/status/due/priority）。
6. `reminders.ts`：保持（只依赖 `metadata.due` + `status==='todo'`），改为从 SQLite 取数据；确保 reload/sync/写后重建通知队列（§4.11）。
7. `index.ts`：导出新模块，移除 `vault.js` 主路径导出（parser/serializer 仅在导出功能内部引用）。

## Phase 3 — 桌面端（Tauri）

1. **Storage 绑定**：`src/platform/tauriSql.ts` 实现 `Storage`（基于 `tauri-plugin-sql`）；复用现有 `TauriFileSystem` 处理 `ops/`、`attachments/`、`exports/`。启动时建库/开 WAL，首启或缺库时 `rebuild`。
2. **store 重构**：`src/state/vaultStore.ts` 改用 `LoopDB`；新增 projects、habits 切片；同步状态机**移除 `pull_required`**（PRD §4.9.1 注）。
3. **Entry UI**：`QuickInput`/`EntryRow`/`EntryDetailPage` 支持 `ongoing`（循环箭头图标、不打勾、首页置顶可在设置关）、`/ongoing`、project chip、关联/解除 project、**升级为 project**（§4.1.3）。
4. **新页面**：`ProjectsPage`/`ProjectDetailPage`（markdown body 渲染+编辑、关联 entry 时间流、内部 `[ ]` 清单不入全局流、归档/删除）/`ArchivedProjectsPage`；`HabitsPage`/`HabitDetailPage`（进度条、热力图、匹配 entry 列表、pause/resume/archive）/`ArchivedHabitsPage`；接入"⋯"菜单与**自适应入口**（无 project/habit 时不显示）。路由加入 `main.tsx`。
5. **快捷键**：`Cmd/Ctrl+P` 项目、`Cmd/Ctrl+H` 习惯、`Cmd/Ctrl+R` 重建本地库（`App.tsx`）。
6. **设置**：`AboutPage` 加「重建本地数据库」；新增 **导出页**（markdown 快照/JSON dump/op log 拷贝，复用 `serializer.ts`）。（不做 AI 配置页 / Prompt 模板管理页 —— AI 功能不在 v2.0 范围。）
7. **MCP 接管**：`src-tauri` 启动时 spawn Node MCP server（如未运行）、App 关闭不杀；向 Claude Desktop 配置注册；`McpServerPage` 调整为管理/开关。

## Phase 4 — 移动端（RN）

按 Phase 3 对等实现：`react-native-quick-sqlite` 注入 `Storage`、`react-native-fs` 处理 ops/attachments；`vaultStore` 切 `LoopDB`；`ongoing` 视觉 + `/ongoing`；新增 Project/Habit 列表/详情屏 + "⋯"自适应入口；升级为 project；同步/通知按新模型；移除 markdown 文件读写。移动端不出现 MCP/全局快捷键入口（§4.10）。iOS/HarmonyOS 原生工程补齐为后续子阶段（不阻塞 Android）。

## Phase 5 — Node.js MCP server（重写，替换 Rust）

- 新建 Node 进程：复用 `@loop/core` 的 `Storage`(better-sqlite3/node:sqlite)、`oplog`、`apply`、repo、`sync`，**与 App 共享同一 `data.db`（WAL）+ `ops/`**。
- 传输：stdio（对接 Claude Desktop/Cursor）+ WebSocket `:9710`（Tool Bridge）/`:9711`（UI Bridge）。
- Tools：实现 PRD §4.8.2 全表（read/write Entry、Project、Habit、`vault_context`、`query_entries`、`ui_*`）。写操作走 op-first + 路径边界 + 异步触发同步；UI tools 经 9711 推送，App 未运行时返回成功不生效。
- 弃用 `apps/mcp-server`（Rust）：确认后移除或归档，`mcp_health_check`/`McpServerPage` 指向 Node 二进制/入口。

> **AI 功能（原计划 Phase 6）不在 v2.0 范围**：不实现「问 AI」按钮、in-app AI 调用层、AI 配置页、Prompt 模板管理页。MCP server（Phase 5）保留——它是给外部 AI 工具的访问通道，不是 in-app AI 功能。

## 验证

**core 单测（Vitest，`packages/core`）**：
- `bun run --filter @loop/core test` 覆盖 §10.3 最小集 + habit 进度 + op-level sync 合并 + 搜索语法 + 回放重建。
- 用 §10.2 样例 op 序列回放，断言 entries=4 / projects=1 / habits=1 / swimming 本周期 1/3-4。

**桌面端 e2e（手动）**：
- 输入框创建 todo/log/done/ongoing 四态；ongoing 置顶；标签高亮可点。
- entry「升级为 project」全流程；关联/解除 project；项目归档/恢复/删除（entry 解关联不删）。
- 习惯创建→记一条带匹配 tag 的 entry→详情页进度即时 +1；改 schedule.target 立即重算；pause 不计、resume 恢复。
- 设置 `due` 的 todo 到期触发一次系统通知；完成/删除/清 due/转 ongoing 后不再触发。
- 删除 `data.db` 后重启自动重建；Cmd/Ctrl+R 重建；写后 `ops/*.jsonl` 为合法可读 jsonl。
- 两个 vault 指向同一 WebDAV 双写同一 entity，按 op 时间序合并不丢数据；离线可用、恢复后自动补发 op。

**MCP（桌面）**：
- Claude Desktop 配置后可见全部 tools（含 project/habit）；读写反映到 App UI；App 关闭后仍可服务；`ui_*` 在 App 运行时触发跳转；越界路径被拒。

**性能抽测（§9.3）**：10k entry 首页 <1s、创建落盘 <100ms、搜索 <500ms、回放重建 10k <5s。

**类型/构建**：`bun run typecheck`、`bun run build` 全绿；桌面 `bun run dev:desktop`、移动 `bun run --filter @loop/mobile android` 起得来。
